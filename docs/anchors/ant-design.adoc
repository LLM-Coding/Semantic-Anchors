====
Full Name:: Ant Design -- "A UI Design Language" (https://github.com/ant-design[GitHub organisation]) and its React implementation `antd`

Also known as:: antd, AntD

[discrete]
== *Core Concepts*:

* *Four design values.* Natural, Certain, Meaningful and Growing; "Certain" aims at "high certainty and low cooperative entropy" (https://ant.design/docs/spec/values[Design Values]).
* *Forms by declaration.* A `Form` holds `Form.Item` fields with `name` and `rules`; `onFinish` receives the validated values, `Form.useForm` gives access to the form instance (https://ant.design/components/form-cn[Form]).
* *Components for dense data.* `Table` with sorting, filters and pagination, plus `Descriptions`, `Tree`, `Transfer` and `Steps` for back-office screens.
* *Three token layers.* Seed tokens are "the origin of all design intent", map tokens derive from them, and alias tokens style groups of components; `ConfigProvider` takes `token`, an `algorithm` for dark or compact themes, and per-component overrides (https://ant.design/docs/react/customize-theme[Customize Theme]).
* *A family of projects.* Ant Design Pro (an admin template), Ant Design Mobile, Ant Design Charts and Ant Design X for AI interfaces sit beside the core library.

Key Proponents:: Ant Group (formerly Ant Financial), with afc163 as its long-time lead maintainer. Released publicly in July 2015 (https://dev.to/logrocket/ant-design-adoption-guide-overview-examples-and-alternatives-3003[LogRocket, 2024]); version 5 in November 2022 (https://ant.design/docs/blog/css-in-js[Ant Design blog]), version 6 in November 2025

[discrete]
== *When to Use*:

* Building admin consoles, dashboards and other back-office interfaces in React with many forms and tables. In our prior test, every anchor run of a sign-up form imported from `antd` and used `Form.Item` with `rules`, `Input.Password` and `onFinish`.
* Theming a whole application from a few seed tokens
* Teams that want a complete, opinionated component set rather than primitives to assemble

[discrete]
== *Common Misunderstandings*:

* *Treating the design language and the library as one thing.* "Ant Design" names both the design specification and the `antd` package; Pro, Mobile and X are separate projects.
* *Expecting the v4 theming API.* Version 4 themed through Less variables; version 5 replaced them with CSS-in-JS tokens, and version 6 defaults to CSS variables.

[discrete]
== *Criticism*:

* *The Christmas easter egg.* In 2018 an unannounced commit made antd 3.9.3 to 3.11.5 show snow on buttons on 25 December in production apps. The maintainer apologised in https://github.com/ant-design/ant-design/issues/13849[issue #13849]: "It is a complete stupid decision of my own and very sorry to everyone that get involved." The Chinese tech outlet TMTPost summed up the reaction: an easter egg from developers to users is a surprise, one from a framework to developers is a scare (https://www.tmtpost.com/3667624.html[TMTPost, 2018]).
* *Weight.* Elijah Asaolu, https://dev.to/logrocket/ant-design-adoption-guide-overview-examples-and-alternatives-3003["Ant Design adoption guide"] (LogRocket, 2024), cautions: "keep in mind that Ant Design components can be heavy."

[discrete]
== *Current Status*:

* *Version 6 with CSS variables.* Ant Design 6.0, released in November 2025, defaults to "pure CSS Variables mode" with an optional zero-runtime build, needs React 18 or later, restructures every component's DOM for semantic styling and removes APIs deprecated in version 4 (https://dev.to/zombiej/ant-design-60-is-released-bfa[release post]). The current release is 6.6.7 of 20 October 2026 (https://ant.design/components/changelog/[Changelog]). Version 6 is newer than most training data; for its specifics, name the version.
