= GoF-Composite Pattern
:categories: design-principles
:roles: software-developer, software-architect
:umbrella: gof-design-patterns
:tier: 3
:definition: The Composite pattern is a structural GoF design pattern by Erich Gamma, Richard Helm, Ralph Johnson and John Vlissides that composes objects into tree structures to represent part-whole hierarchies. Individual objects and compositions share one interface, so clients treat them uniformly and can ignore the difference between a single object and a group, as when files and folders in a file system are handled the same way.
:proponents: Erich Gamma, Richard Helm, Ralph Johnson, John Vlissides

Full Name:: GoF Composite Pattern (Structural)

[discrete]
== *Intent*:
Compose objects into tree structures to represent part-whole hierarchies. Composite lets clients treat individual objects and compositions uniformly.

[discrete]
== *When to Use*:
* When you want to represent part-whole hierarchies of objects
* When you want clients to be able to ignore the difference between compositions of objects and individual objects

[discrete]
== *Prompt Example*:
"Modelliere das Dateisystem nach dem GoF-Composite Pattern, sodass Dateien und Ordner einheitlich behandelt werden können."
