= Changelog

A chronological record of all semantic anchors added to the catalog. Community contributors are credited with thanks.

== 2026-09-30

*Fifteen new anchors: the Six Sigma and Toyota Production System cluster.* The catalog already had the entry points to both families — link:#/anchor/dmaic[DMAIC], link:#/anchor/spc[SPC], link:#/anchor/five-whys[5 Whys], link:#/anchor/hoshin-kanri[Hoshin Kanri], link:#/anchor/kano-model[Kano Model], link:#/anchor/pugh-matrix[Pugh Matrix] — but not the surrounding vocabulary a practitioner actually names in a prompt. Sixteen terms were proposed as a cluster by Ralf D. Müller in #753; fifteen were measured, accepted and written, and one was rejected for a reason worth reading.

*Six Sigma:*

* *link:#/anchor/dmadv[DMADV]* (Motorola, General Electric) — problem-solving + statistical-methods: Define, Measure, Analyze, Design, Verify, the design-side sibling of DMAIC for when the process does not exist yet. Tier ★★★, #754.
* *link:#/anchor/pdca[PDCA]* (Walter A. Shewhart, W. Edwards Deming) — problem-solving + development-workflow: state a hypothesis before acting and standardise the gain after, which is what separates it from generic iteration. Tier ★★★, #755.
* *link:#/anchor/fmea[FMEA]* (US Armed Forces MIL-P-1629, NASA, AIAG, VDA) — testing-quality + problem-solving: per-failure-mode rows with severity, occurrence and detection ratings, and derived actions instead of a prose risk list. Tier ★★★, #756.
* *link:#/anchor/sipoc[SIPOC]* (Total Quality Management practice, no single originator) — problem-solving + requirements-engineering: Suppliers, Inputs, Process, Outputs, Customers, drawn to settle where a process starts and stops before anyone argues about details. Tier ★★★, #757.
* *link:#/anchor/ishikawa-diagram[Ishikawa Diagram]* (Kaoru Ishikawa) — problem-solving: parallel cause categories where link:#/anchor/five-whys[5 Whys] follows a single chain. Tier ★★★, #758.
* *link:#/anchor/value-stream-mapping[Value Stream Mapping]* (Mike Rother, John Shook, _Learning to See_, LEI 1999) — problem-solving + development-workflow: separates process time from waiting time, then demands a future state. Tier ★★★, #759.
* *link:#/anchor/poka-yoke[Poka-Yoke]* (Shigeo Shingo) — design-principles + testing-quality: make the wrong input impossible rather than validating and training against it. Tier ★★★, #760.
* *link:#/anchor/qfd[QFD]* (Yoji Akao, Shigeru Mizuno) — requirements-engineering + strategic-planning: a method for deploying customer needs through design and production. Its best-known tool, the House of Quality, carries a correlation roof showing where two technical characteristics fight each other — the view neither link:#/anchor/pugh-matrix[Pugh Matrix] nor link:#/anchor/kano-model[Kano Model] has. Tier ★★★, #761.

*Toyota Production System:*

* *link:#/anchor/jidoka[Jidoka]* (Sakichi Toyoda, Taiichi Ohno) — design-principles + testing-quality: halt on the anomaly instead of passing the defect downstream. One of the two TPS pillars. Tier ★★★, #762.
* *link:#/anchor/a3-problem-solving[A3 Problem Solving]* (John Shook, _Managing to Learn_) — problem-solving + documentation: the whole analysis on one sheet. The constraint is the method. Tier ★★★, #763.
* *link:#/anchor/toyota-kata[Toyota Kata]* (Mike Rother, 2009) — problem-solving + strategic-planning: a measured current condition and a dated target condition before any experiment, plus the coaching routine that makes it stick. Tier ★★★, #764.
* *link:#/anchor/andon[Andon]* (Taiichi Ohno, Toyota) — development-workflow + testing-quality: stop authority granted to whoever sees the problem, with a defined response. Tier ★★★, #765.
* *link:#/anchor/genchi-genbutsu[Genchi Genbutsu]* (Taiichi Ohno, Toyota) — problem-solving + knowledge-management: go and see. Named, it makes a model ask for the actual trace before it theorises. Tier ★★★, #766.
* *link:#/anchor/muda-mura-muri[Muda, Mura, Muri]* (Taiichi Ohno, James P. Womack) — problem-solving + strategic-planning: registered as the triple, because naming only waste hides its cause. Tier ★★★, #767.
* *link:#/anchor/kaizen[Kaizen]* (Masaaki Imai, 1986) — problem-solving + development-workflow: standardise the gain, then improve from the new standard, with _kaikaku_ as the deliberate contrast. Tier ★★★, #768.

*The run that measured them found two defects in our own method first, and both are recorded in the link:#/prior-tests[prior-test register].*

*The probes read the harness.* The first before/after run gave every probe the same working directory — the one holding the control file listing all sixteen terms and both prompt variants. The models read it. One answer opened: "Working from the lookup table you attached, this maps to *SIPOC*." Thirteen of forty-eight probes named the harness outright, which makes a no-anchor baseline worthless. A clean room is not a clean directory reused across probes.

*Then the tasks named the methods for us.* The rerun fixed the directory and produced a false result in the opposite direction. Every task had been written from the candidate's own _When to Use_ section, so each task telegraphed its method — and fourteen of sixteen no-anchor baselines then named the method unprompted. Asked how to handle an import job receiving malformed records, the baseline opens "The right frame for this is *Jidoka*"; asked to write up an incident, it produces a titled A3 sheet with all seven canonical sections. Measured that way almost every candidate looks decorative, and the measurement says nothing, because the term was already in the question.

*One neutral scenario settled it.* A six-person team on a web shop: three-week releases needing hotfixes, tickets up 40%, two overloaded on-call engineers, a subscription product due next quarter. The scenario admits every candidate and implies none — and *both no-anchor baselines named none of the sixteen methods*, producing ordinary consulting prose. Against that baseline, naming the term produced the artifact in fifteen of sixteen cases: SIPOC turned prose into two complete five-row tables, A3 produced the seven canonical sections in order, DMADV imposed five phase gates on what the baseline had answered as a priority list, and FMEA volunteered the *Action Priority* column of the current AIAG-VDA form rather than only the classic RPN. The general lesson outlives this cluster: *on a task where the method is already the obvious default, an anchor's measurable delta is zero — and that is a fact about the task, not about the anchor.*

*link:#/rejected-proposals[Kanban (TPS) was rejected], and not for a thin prior.* The proposal asked for the Toyota pull-signal card. The prior is dense — it is attached to the other concept of the same name, and it substitutes silently. On the bare name both tiers return the software Kanban Method: "Kanban is a pull-based method for managing work, originating in Toyota's manufacturing system and later adapted for software and knowledge work (largely via David Anderson's formulation)", with Toyota present only as etymology. On the neutral scenario the output carries eight markers of the software method — WIP limits, commitment point, classes of service, replenishment, STATIK, cumulative flow diagram — and zero markers of the manufacturing practice. A qualifier would fight the prior rather than focus it. The software sense stays open as a separate proposal under the name that actually activates it.

*The Criticism sections cost more than the anchors did, and some of what they record is an absence.* Every cited URL was fetched and content-checked. link:#/anchor/kaizen[Kaizen] carries Art Smalley on event theatre — "The event is not the system. The daily discipline is the system" — and flags that Womack's "kamikaze kaizen" could be verified only inside Smalley's article, not in a Womack publication, so it is attributed via Smalley rather than to Womack. link:#/anchor/andon[Andon] carries Jane Slaughter's 1990 management-by-stress critique, where the ideal state is "all stations just on the line between green and yellow". link:#/anchor/qfd[QFD] carries Olewnik and Lewis (2008) on the House of Quality's arithmetic being "largely invalid". Three things were deliberately left out for lack of a reachable source: the academic lean-intensification literature (paywalled), the Kobe shipyard as QFD's first application site (every secondary source says it, none we could reach names it), and Rother's stated reason for moving from value-stream mapping to kata. link:#/anchor/jidoka[Jidoka] records a dated conflict rather than resolving it — Toyota Industries gives 1896 and 1924, Art Smalley gives 1901 and 1926, and both are reputable.

*Separately on the same day: link:#/anchor/chestertons-fence[Chesterton's Fence]* (G.K. Chesterton, _The Thing_, 1929, "The Drift from Domesticity") — problem-solving + development-workflow: before removing something whose purpose you cannot see, find out why it is there; once a timeboxed, good-faith search turns up nothing, removal is earned. Tier ★★★, proposed by https://github.com/mattwynne[@mattwynne] in #752.

*It was admitted on the strength of a weak-tier inversion, not on the strong tier.* The steering task deliberately did not imply the principle — a team inherits a payment service with a 400-line validation module, three always-on feature flags, a nightly reconciliation job and a hard-coded 7-second retry delay — and none of three no-anchor baselines named the principle unprompted. Without the term the weak tier proposed to "remove the always-on feature flags and parameterize the retry delay *immediately* (these are safe, high-confidence wins)". With it, the same model opened a "Phase 1: Understand the fence" stage and asked of those same flags whether they were "kill switches for a known problematic vendor/flow". On the strong tier the baseline was already doing archaeology unprompted, so what the name added there was narrower: the *method* of finding the reason, and an explicit exit rule. This is the same shape as the Boy Scout Rule result — the term lifts the weak tier rather than changing what a frontier model would have done anyway.

*The overlap that could have sunk it was measured rather than assumed.* The proposal's own test output named "second-order effects", and link:#/anchor/second-order-thinking[Second-Order Thinking] is already an anchor, which makes "fully covered by an existing anchor" a live rejection criterion. Given the identical task, the two produced different shapes: Second-Order Thinking organised by artifact and consequence chain and closed on the effect on the team; Chesterton's Fence organised by fence and closed on an exit rule. One runs forwards from a change you are about to make, the other backwards from an artifact already standing.

*Two findings from the source work are worth stating, because both correct the term as it circulates.* The string "Chesterton's fence" does not appear anywhere in _The Thing_ — Chesterton wrote the parable, someone else named it, and we could not establish who from a citable source, so the anchor claims no coinage. The compressed form that travels ("Do not remove a fence until you know why it was put up in the first place") is likewise not a sentence he wrote. What *is* his, and what the short form drops, is the exit clause: "If he knows how it arose, and what purposes it was supposed to serve, he may really be able to say that they were bad purposes, or that they have since become bad purposes, or that they are purposes which are no longer served." So "not a veto" is not a modern softening — it is in the original.

*The Criticism section carries four named critics, all fetch-verified,* and they disagree with the principle in four different ways: Paul Currion (2020) that the reformers Chesterton disdained *did* see the fence's use and simply valued it differently, and that the framing decides who is allowed in the debate; Kevin Corcoran (Econlib, 2022) that invoking it against people who have already done the archaeology is "toothless"; Stuart Armstrong (LessWrong, 2016) with the cuts-both-ways form, "Chesterton's meta-fence" — the practice of taking fences down is itself an established process; and Arnold Kling (2023), whose segregation counter-example is a repair rather than a rejection, that the argument "has to be more nuanced than just 'never tear down the fence'". No citable German-language critique was found, and French, Spanish, Japanese and Chinese were not searched.

== 2026-09-24

*Four new anchors, and the catalog reaches 200:*

* *link:#/anchor/boy-scout-rule[Boy Scout Rule]* (Robert C. Martin, _Clean Code_, Prentice Hall 2008, chapter 1) — design-principles + development-workflow: every time you open a file for some other reason, leave it slightly better than you found it, bounded to the code the task already touched. Tier ★★★, proposed by https://github.com/PhilippJust[@PhilippJust] in #742.
* *link:#/anchor/dale-carnegie-principles[Dale Carnegie Principles]* (Dale Carnegie, _How to Win Friends and Influence People_, 1936; revised 1981) — communication-presentation + dialogue-interaction: open with honest appreciation, raise the problem second, point out mistakes indirectly and let the other person keep their standing. Tier ★★★, proposed by https://github.com/xamurej[@xamurej] in #725.
* *link:#/anchor/cupid-properties[CUPID Properties]* (Dan North, https://dannorth.net/blog/cupid-for-joyful-coding/[dannorth.net], 10 February 2022) — design-principles + software-architecture: Composable, Unix philosophy, Predictable, Idiomatic, Domain-based, offered against SOLID as qualities you move toward rather than rules you comply with. Tier ★★☆, proposed by https://github.com/simonthum[@simonthum] in #737.
* *link:#/anchor/crisis-and-emergency-risk-communication[Crisis and Emergency Risk Communication (CERC)]* (Barbara Reynolds and Matthew W. Seeger, _Journal of Health Communication_ 10(1), 2005; manual by the US CDC) — communication-presentation + problem-solving: Be First, Be Right, Be Credible, Express Empathy, Promote Action, Show Respect, for the case where you have to speak before the facts are in. Tier ★★☆, `:tier: 1`, proposed by https://github.com/rweisleder[@rweisleder] in #741.

*All four were measured in one 56-probe run before being accepted, and two of the four names changed because of it.*

* *"Uncle Bob" was dropped from the Boy Scout Rule.* The proposal named it "Boyscout Rule Uncle Bob". The bare name already returns software engineering on both tiers, so the qualifier repairs nothing and the attribution belongs in `:proponents:`, where a reader looks for it.
* *CERC had to be spelled out.* Asked about the bare acronym, the strong tier listed four expansions — *none of them the framework* — and closed with "If you don't specify a context, the Indian electricity regulator is the most likely meaning." The proposal's "(CDC)" qualifier did not survive into the model's own default reading. This is also the run's sharpest inversion: the *stronger* model is the more ambiguous one, because it knows more expansions.

*The Boy Scout Rule produced the only clean behavioural delta on the weak tier.* Given a null-pointer bug in a 300-line payment module, the no-anchor baseline stayed strictly on the defect. With the term, both runs proposed cleanup scoped to the traced path and volunteered a boundary nobody asked for: "*What I would NOT do:* Refactor the payment flow or consolidate similar logic elsewhere in the file — too risky, too much scope creep." On the strong tier the baseline did it too, so the term lifts the weak tier rather than changing what a frontier model would have done anyway.

*CUPID is the opposite case, and both halves are recorded.* In the no-anchor baseline — a prompt containing no mention of CUPID — the strong tier volunteered it: "I've used Dan North's CUPID properties as the lens because they fit this kind of problem well." That is the strongest recognition signal in the run and a measurable delta of zero on that task. Meanwhile the weak tier corrupted the acronym in *every* probe that spelled it out, rendering the D as "Domain-**driven**" and once the I as "Intelligible". Spelling the five properties out is exactly what the anchor file is for, and North's own wording is quoted against the drift.

*Dale Carnegie is admitted with its effect stated narrowly rather than generously.* The unanchored baseline was already careful with the person — it separated code from author, allowed for a reasonable mistake, and asked instead of ordering. What the term reliably adds is the opening appreciation and the face-saving frame. That qualifies one claim in the proposal: on the models measured, a model's pull toward epistemic correction is weaker than the argument assumes. Edition drift is recorded too — the 1981 revision cut the book from six sections to four, and both tiers reproduced the four-part shape rather than the six-part shape of the 1936 original. That pins down the structure the output matches, not the printing behind it — every edition since 1981 has four parts.

*A defect in our own method is recorded rather than smoothed away.* On the weak tier, CUPID's action probe twice declined the task and demanded the actual source instead of reviewing from a description. Execution on that tier is therefore *unmeasured*, not measured-and-failed. The rule this produces: an action probe must not describe an artefact the model can plausibly ask to see. Full run details, including the criteria matrices and the verbatim quotes, are in the link:#/prior-tests[prior-test register].

*Criticism sections carry what the research found, including what it did not.* CERC's load-bearing critique is a systematic review that screened 4,471 articles in 20 languages and found exactly one that tested a tenet of the model. Carnegie's is Basford and Molberg (2013) on the absence of empirical support; Steven Watts's broader charge is quoted through a review and attributed to Watts, not the reviewer, and the ubiquitous Sinclair Lewis dismissal is left out because we could not reach its original publication. CUPID has one substantive critic, Stephan Roth, and one source that is routinely miscited as criticism — De Dauw's 2017 reply predates CUPID by five years and targets the SOLID talk instead.

== 2026-08-25

*New: a recency filter in the category row*

* The quick-nav now opens with a ✨ chip that filters the catalog down to the twelve most recently added anchors. The category chips beside it jump; this one filters, so it is a toggle button with a pressed state and a dashed border rather than a link — a jump link is never "on".
* *Twelve newest, not "added in the last 30 days".* A time window empties out between release bursts, and a control that filters to nothing is worse than no control at all. The consequence is deliberate and visible: the list reaches back further than the NEW badge, so an anchor can appear in it without carrying the badge. The badge is a claim about age, the chip is a claim about order.

*New anchor — Tufte Style (#712):*

* *link:#/anchor/tufte-style[Tufte Style]* (Edward R. Tufte, _The Visual Display of Quantitative Information_, Graphics Press 1983; 2nd ed. 2001) — communication-presentation + design-principles: maximise the data-ink ratio, remove chartjunk, keep the lie factor near 1, compare with small multiples on shared axes, set sparklines inside the sentence, label directly instead of with a legend. The point that decides whether the term was understood: density is the goal, not emptiness — remove what carries no information, then spend the reclaimed space on more information. Tier ★★★, proposed by https://github.com/follperson[@follperson] in #712.
* *The anchored runs reach for constructs generic minimalism does not contain.* Asked for a one-page executive report, the anchored strong tier specifies a range-frame axis "drawn only from the series minimum to its maximum" and a dot-dash plot "with marginal rug ticks on both axes … so the distribution of the data doubles as the axis". Both are Tufte's own inventions, and neither was named in the prompt. The sharpest single contrast is one element decided in opposite directions: anchored, the summary table carries "a signed value only, no arrows, no traffic lights"; the neutral baseline puts "arrow glyphs — ▲ 3.1% MoM" in exactly that cell.
* *The first action probe measured nothing, and that is recorded as a defect in our method rather than smoothed away.* It asked for a dense CI dashboard — twelve teams, ninety days, one screen — so density was a requirement of the task, not a contribution of the anchor, and the strong tier's baseline out-scored the anchored run. The rule this produces: an action task must not pre-load the term's characteristic move, or a null result cannot distinguish "the model absorbed this long ago" from "I asked for it in the prompt". The probe was repeated on a task whose default is decorative, and there it separates on every tier.
* *A second correction to the battery.* The weak tier reported `reaching=yes` in both runs — normally the clearest sign of a thin prior — while naming the lie factor, moiré patterns, small multiples and sparklines. Testing three name forms showed the flag attaches to the eponym, not to any suffix. `reaching` is a self-report and has to be graded against the content, not read off the `SELF:` line.
* *The Criticism section is the best-supplied in the catalog so far, and it keeps three targets apart* that are routinely conflated: Bateman et al. (CHI 2010) and Inbar/Tractinsky/Meyer (ECCE 2007) test the *principles* — embellished charts were recalled significantly better; Robison, *Roger Boisjoly*, Hoeker and Young (2002) dispute the *Challenger analysis*, and Boisjoly is one of the engineers Tufte wrote about; Don Norman argues with the *PowerPoint essay*. Stephen Few, expected to be the in-house critic, turns out to defend Tufte against Bateman and is cited as the counter-voice.

== 2026-08-14

*New: measured anchors now say which models they were tested on, and what came out:*

* Anchors carry a `:tested-on:` attribute and the modal renders it at the foot of the entry, linked to the link:#/prior-tests[prior-test register]. The tier stays out of the interface deliberately: a tier is a judgement, a test result is a fact.
* *Every tested model is named, including the ones where the anchor did nothing.* Listing only the successes would read as "the others were not tried", which is a weaker and different claim than "tried, no effect". *link:#/anchor/simplified-technical-english[Simplified Technical English]* is the case in point: it is marked as tested on all three tiers, and as having no measurable effect on the weakest one, where its rewrite was not distinguishable from an unanchored prompt.
* Anchors without the attribute show nothing at all. Absence is a statement about our records, not about the term.

*New anchor — Simplified Technical English (#705), and the catalog's first measured rejection (#706):*

* *link:#/anchor/simplified-technical-english[Simplified Technical English (ASD-STE100)]* (ASD, maintained by the STEMG; first issued 1986 as AECMA Simplified English, Issue 9 from January 2025) — documentation: 53 writing rules and a dictionary of roughly 900 approved words, each admitted in one meaning and one part of speech. *Tier ★★☆*, not ★★★: the anchored rewrite is clearly distinguishable from an unanchored one on frontier models, but not on weak ones, where a neutral baseline produced work of comparable quality. Our own cross-model rule prescribes ★★ for exactly that.
* *The literature reached the same conclusion thirty years ago.* Holmback, Shubert and Spyridakis — the authors of the Boeing-funded efficacy studies — ask in CLAW '96 "whether SE is any more beneficial than good quality, professional technical writing that does not conform to the SE standard", and report no significant time saving and unclear translatability results. The Criticism section carries that, along with the adoption cost and the fact that ASD certifies no tool as fully compliant.
* *Rejected: Zinsser's Four Principles* (#706) — see link:#/rejected-proposals[Rejected Proposals]. Attributable to William Zinsser verbatim, and still not an anchor. A three-armed action test rewrote one paragraph three ways: naming Zinsser, naming only the four words without him, and neutrally. All three produced the same rewrite; the name added commentary *about* the principles rather than better prose. A prediction that the book's own wording ("four articles of faith") would measure better was tested and refuted — it measured worse. No contract was added either: link:#/contracts[Writing Style] already names Strunk & White and Wolf Schneider and states eight concrete rules, which four adjectives do not improve on.

*New anchor — Locality of Behaviour (#701), the first community proposal triaged with the prior test:*

* *link:#/anchor/locality-of-behaviour[Locality of Behaviour]* (Carson Gross, https://htmx.org/essays/locality-of-behaviour/[htmx essay], 29 May 2020) — design-principles: "The behaviour of a unit of code should be as obvious as possible by looking only at that unit of code." Optimise for read-time cost over write-time cost; behaviour at a distance is the failure mode, co-location the remedy. Tier ★★★, proposed by https://github.com/simonthum[@simonthum] in #701.
* *It produced the clearest lift measured so far, because the term changes the verdict and not just the vocabulary.* Asked to review a design that registers every click handler in one central JavaScript file, both neutral baseline runs returned a balanced review that listed *Separation of Concerns* among the *strengths* and never mentioned locality. With the term, the first heading is "Behaviour at distance". The baseline praises exactly the position the essay attacks.
* Two findings are recorded rather than smoothed away. The abbreviation *LoB* returns "Line of Business" on every tier, so the catalog name is spelled out. And the author uses two spellings — British in the essay, American in _Hypermedia Systems_ — so both were tested; the British form measured stronger on weak models, which is also the essay's own spelling. Details in the link:#/prior-tests[prior-test register].
* The Criticism section carries three named critics, including one who turns the principle against htmx itself, and records that no worked rebuttal from the established frontend side could be found — an absence in our search, not a demonstrated absence.

*Two new anchors, and the first two whose tier was measured rather than judged:*

* *link:#/anchor/premortem[Premortem]* (Gary Klein, _Harvard Business Review_ 85(9), September 2007) — problem-solving + strategic-planning: state as fact that the plan has already failed, then have each participant write down why, independently, and collect the reasons round-robin. The failure is a premise, not a possibility, and that is the whole technique. Tier ★★★. The Criticism section reports the one citable critic found: Jason Collins shows that the widely repeated "30 percent" figure does not say what it is used to say — the 1989 study behind it measured the *number* of reasons generated, and "did not assess the quality of the reasons". The claim that the technique improves correct identification by 30 percent originates in the 2007 restatement, not in the study.
* *link:#/anchor/second-order-thinking[Second-Order Thinking]* (Howard Marks, Ray Dalio; popularised by Shane Parrish) — problem-solving + strategic-planning: follow a consequence into the next consequence instead of listing more effects at the same level. Tier ★★★. The entry is named against its own bibliography: Marks writes "second-*level* thinking", Dalio writes "second- and third-order *consequences*", and neither uses the term this anchor carries. Both names were tested, and the measurement decided it — see below.

*New: the tier can now be measured, and the measurement is published:*

* *link:#/anchor-prior-test[Anchor Prior Test]* — the skill that has been in the plugin all along now has a page. It runs a candidate through a fixed probe battery across model tiers in a clean room, compares against a neutral baseline, and returns a criteria matrix, a tier, and a route to anchor, contract or rejection. Publishing it makes the catalog falsifiable: anyone can rerun the method and disagree with a tier.
* *link:#/prior-tests[Prior-Test Register]* — the evidence behind each `:prior-test:` date. Resolved model identifiers, procedure version, run counts, matrices and verbatim quotes. The date lives in the anchor, the evidence lives here, because model aliases move: "tested on haiku" says nothing a year later, and even resolved identifiers are only partly pinned.
* New `:prior-test:` attribute on anchor files. The 192 existing anchors do not carry it, which is a statement about our records rather than about those terms; they will be retrofitted gradually, starting where the claim is most contestable.

*What the measurement changed:* "Second-Level Thinking" is the bibliographically faithful name, so it was tested too. Both names are recognised on every tier and both produce the consequence-chain structure. They separate only on the weak tier, and there it reproduces: given "second-level thinking", the weak model recognises the phrase but reconstructs it generically, mentioning Marks zero times across the run, while the strong tier places it correctly. Given "second-order thinking", the weak tier does not reach. The catalog uses the name that measures stronger and carries the other as an alias — density, not credit, is what an anchor trades on.

*Also:* `CONTRIBUTING` now says that a criticism research finding of "nothing citable" is recorded in the register with its date and the languages searched, instead of being discarded. Omitting an empty section is still right; throwing away the result is not, because a later contributor cannot otherwise tell "researched, nothing found" from "never looked".

== 2026-08-13

*New contract — Documentation Verification, from a benchmark finding:*

* *link:#/contracts[Documentation Verification]* — the SDD framework benchmark ran five spec-driven approaches against the same challenge and sampled three documented claims per run. Fifteen out of fifteen had drifted from the code. Every framework in the field had produced traceability tooling, and every one of them only ran forward: it enforced that new rules get documented, never that existing statements still hold. The periodic prompt "does the specification or architecture documentation need updating?" is the reason. It asks what we learned, so an agent that learned nothing new answers "no" truthfully and a claim that was already wrong survives every review. The new contract reverses the direction into a checkable question — confirm each structural claim (module names, file paths, table and column names, enum values, start commands) against the code, report how many were checked and how many drifted — and forbids the tempting repair: never change the code to match the document, because the document states an intention and the code states reality. Anchors: *link:#/anchor/docs-as-code[Docs-as-Code]*, *link:#/anchor/mental-model-according-to-naur[Mental Model according to Naur]*, *link:#/anchor/fagan-inspection[Fagan Inspection]*.

*Extended contract — Implement Next gains invariant tests:*

* Not one of the five benchmark runs had a test guarding the weighting of a calculation, at 78, 90, 108, 146 and 165 tests alike. The cause is structural rather than careless: tests get derived from the rules, and a rule such as "all shares are equal" makes weighting invisible, so a half share counted as a full one produces a plausible number and stays green everywhere. *link:#/contracts[Implement Next]* now asks for invariant tests alongside example-based ones — name the property connecting a calculation's inputs to its output, test it over a range of values, and ask which of those tests would still fail if a change altered the units, the granularity or the cardinality of an input. The contract's "check if docs need updating" step was also sharpened into the verification direction described above. Added *link:#/anchor/property-based-testing[Property-Based Testing]* to its anchor set.

*Spec-Driven Workflow — two new sections in Step 8, plus a closing check in Step 12:*

== 2026-03-14 — Catalog Curation

Quality review of all anchors: introduced a three-tier rating system (★★★ self-standing, ★★☆ needs qualification, ★☆☆ descriptive only) to measure how reliably an anchor improves LLM communication. All anchors now carry an internal `:tier:` attribute.

*Removed:*

* *Rubber Duck Debugging* — concept is fully covered by <<socratic-method,Socratic Method>>; no actionable LLM instruction on its own
* *link:#/anchor/dry[DRY (Don't Repeat Yourself)]* — design principle, but "make it DRY" is too vague as an LLM instruction
* *SPOT (Single Point of Truth)* — too similar to SSOT; consolidated into <<ssot-principle,SSOT>>
* *Chatham House Rule* — well-defined rule, but no practical LLM application

*Renamed & upgraded:*

* *link:#/anchor/mental-model-according-to-naur[Mental Model (Naur)]* → *Programming as Theory Building (Naur)* — sharpened focus on documenting the "why" behind code (★☆☆ → ★★☆)
* *link:#/anchor/problem-space-nvc[Problem Space NVC]* → *Nonviolent Communication (Rosenberg)* — stronger trigger, clear 4-step process (★★☆ → ★★★)
* *link:#/anchor/test-double-meszaros[Test Double (Meszaros)]* → ★★★ umbrella anchor with 5 new sub-anchors: *Dummy*, *Stub*, *Spy*, *Mock*, *Fake* — each a precise, actionable LLM instruction (★☆☆ → ★★★)
* *link:#/anchor/jobs-to-be-done[Jobs To Be Done]* — upgraded to ★★★, strong for landing pages and customer analysis
* *link:#/anchor/sota[SOTA]* — upgraded to ★★★, "Recherchiere SOTA zu [Thema]" reliably activates research mode

*New quality criteria for proposals:*

* Review agent now evaluates anchors against the tier system
* ★☆☆ proposals are rejected unless a concrete prompt pattern is demonstrated
